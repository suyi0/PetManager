# 3.1.2 系统体系架构设计

本系统采用三层体系架构进行设计，整体划分为用户界面层、领域逻辑层和技术服务层。三层架构能够将前端展示、业务处理和底层技术能力进行分离，使系统结构清晰、模块职责明确，便于系统的开发、测试、维护与扩展。结合本项目“宠物医院管理系统”的实现情况，系统体系架构如图 3-1 所示。

第一层为用户界面层，主要负责提供用户交互界面，并将用户操作请求提交给后端服务。结合本项目的实现，用户界面层主要由前端 Vue 应用构成，包含登录注册页面、普通用户端页面、医生端页面、仓库管理员端页面和超级管理员端页面等内容。其中，普通用户端主要实现预约、订单查询和个人资料维护等功能；医生端主要实现工作台、候诊队列、预约列表、用户档案和创建订单等功能；仓库管理员端主要实现库存维护、库存预警和操作日志查看等功能；超级管理员端主要实现用户管理、医生权限管理和工时管理等功能。用户界面层的核心作用是根据不同角色提供对应的功能入口和可视化操作界面。

第二层为领域逻辑层，主要负责实现系统的核心业务逻辑，是整个系统功能实现的中心部分。结合本项目代码结构，领域逻辑层主要由后端路由层和业务处理模块共同组成。系统在该层中可进一步划分为认证管理、用户管理、预约管理、订单管理、医生管理、仓库管理和后台管理等多个业务模块。认证管理负责注册、登录、验证码校验和管理员令牌刷新；用户管理负责用户资料维护和头像上传；预约管理负责预约记录的创建、查询、修改、取消和删除；订单管理负责订单创建、订单记录查询和订单详情展示；医生管理负责医生出诊状态维护、候诊队列和工作台业务处理；仓库管理负责库存信息的增删改查；后台管理负责普通用户创建删除、医生权限授予撤销以及医生工时调整等功能。领域逻辑层通过对业务模块的划分，使系统功能实现更加清晰，也便于后续扩展新的业务功能。

第三层为技术服务层，主要负责为领域逻辑层提供通用的底层技术支持。结合本项目，技术服务层主要包括数据持久化服务、安全服务、日志服务、中间件服务和定时任务服务。数据持久化服务主要由数据库管理模块完成，负责访问 MySQL 数据库，实现用户、预约、订单、仓库物资和工时记录等业务数据的存储与读取。安全服务主要负责密码加密、JWT 令牌生成与校验、身份认证和权限控制，确保不同角色只能访问对应权限范围内的接口。日志服务主要负责记录用户操作信息和系统运行过程中的关键行为，为后续问题排查和管理审计提供依据。中间件服务主要负责跨域处理和请求限流，在高频访问条件下保证系统接口的安全性和稳定性。定时任务服务则用于处理验证码清理、系统定期维护以及部分业务状态更新等后台任务，提高系统运行的自动化程度。

在本系统中，用户界面层通过前端页面发起 HTTP 请求访问后端接口，领域逻辑层接收请求后完成具体业务处理，并调用技术服务层中的数据库访问、安全认证、日志记录和中间件能力，最终将业务处理结果返回给前端。通过这种分层设计，系统能够在保证功能完整性的同时，降低各模块之间的耦合程度，提高系统的可维护性和扩展性。

## 3.1.3 各层与项目实现的对应关系

为使系统体系架构与项目实现保持一致，本项目中各层与实际代码的对应关系如下。

1. 用户界面层  
用户界面层对应前端工程中的页面、组件、路由和状态管理等内容，主要位于 `pethospital/frontend/src` 目录下。该层按照角色划分为普通用户模块、医生模块、仓库管理员模块和超级管理员模块，分别负责不同角色的界面交互逻辑。

2. 领域逻辑层  
领域逻辑层对应后端工程中的路由和业务处理代码，主要位于 `pethospital/backend/routes` 与 `pethospital/backend/controllers/modules` 目录下。该层负责接收前端请求并实现核心业务逻辑处理。

3. 技术服务层  
技术服务层对应数据库访问、认证授权、中间件、日志和定时任务等基础能力模块，主要位于 `pethospital/backend/database`、`pethospital/backend/controllers/auth`、`pethospital/backend/middleware`、`pethospital/backend/controllers/OperationLogger` 和 `pethospital/backend/utils/ScheduledTaskManager` 等目录下。

## 3.1.4 体系架构设计说明

本系统采用三层架构的原因主要体现在以下几个方面：

1. 前后端职责分离明显，适合采用分层架构组织系统结构。
2. 系统业务角色较多，不同模块之间需要通过统一的后端逻辑进行协同。
3. 系统存在数据库访问、认证授权、日志记录和定时任务等公共技术能力，适合沉淀到技术服务层统一管理。
4. 三层架构便于后续增加新的角色模块、新的业务处理流程和新的技术支撑能力。

图 3-1 展示了系统三层架构的整体关系，其中用户界面层位于最上层，负责与用户交互；领域逻辑层位于中间层，负责业务处理；技术服务层位于底层，为系统提供持久化、安全、日志和中间件等通用支撑。
